Sorter Control
The Sorter Control Module uses standardized tracking control functions (shifter / sorter), along with specific sorter logic to provide scanner input and error processing, container tracking, and management of full conditions, bad gap processing and WCS interface management.
Multiple sorters may be configured within a single AC.
Activating the Module
The sorter module is activated in several separate portions as “Batch jobs” using table Batches:
Srt App SERV – Required to run the SERV portion for managing messages to and from the WCS business logic layer (CommCore).
Srt App CTRL – Required to run the CTRL portion for managing hardware control logic.
Srt Sim SORT – Required to run the simulation features using the SORT process.
The various tables required to configure and use these features are described below.
The Sorter Application Configuration Table – Top Level
The “App Sorter Configuration” or SrtAppConfig table is the top-level definition of a sorter.  It creates the logical representation of the sorter entity.  Other tables are used to define details about the physical and logical characteristics of the sorter.  They will all reference the entry in SrtAppConfig.  This top-level table is used to define the interface to CommCore, how containers with no valid destination are to be handled, the amount of log file detail and the motor that controls the main sorter.

SrtAppConfig Table
Field
Type
Value or Description
Name
String
Enter a descriptive name for the sorter.
Status
String
Indicates the current status of the Sorter including any configuration errors detected.
MtrStatus
String
Indicates the current status of the sorter motor, based on the lane full processing logic.  The motor may be stopped by other logic that is not included in the StrAppConfig status.
SendAvailStatus
Y/N
Set to Y to include the list of unavailable lanes in the CRR Message.  CommCore can use the list to assist in making routing decisions.  The unavailable lanes will appear as a comma-separated list in the sZone1 field of the CRR message (column Dat12).  Set to N for a CRR message that does not include the list of unavailable lanes.  A lane is unavailable if it is full or disabled.
AvailAppSorter
Int
This field may be used to report the list of unavailable lanes from a different sorter via the CRR message.  A value of 0 will report the unavailable lanes for this sorter.  If the unavailable lanes status from another sorter defined on this AC is needed, set the value to the row number in this table of the desired sorter.
For example, if routing to the shipping sorter from the picking sorter may only occur when the shipping zone is not full, the status of the shipping sorter is needed to route the container to the correct location.
ErrConfig
PopUp
Select the error processing method for the sorter.  This will determine how a container will be handled if the destination lane or lanes is/are not available because they are full or disabled.
N/A:  The conveyor will not be stopped, and cartons will not be dynamically re-assigned.
Stop if Not Avail, Single lane assigned:  For applications where the sorter needs to stop if the lane is unavailable.  Also set AssignIfFull to Y.  The sorter will stop when the container reaches the window defined by the SrtLaneNotAvail table.
Stop if Not Avail, Multiple lanes assigned:  For applications where the sorter needs to stop if none of the assigned lanes are available.  The sorter is stopped to wait for one of the lanes to become available.  Once a destination becomes available, the container will be assigned, and the conveyor will start.  Note: The SrtLaneNotAvail table must have at least one entry for this sorter or the sorter motor will not be stopped.  In addition, the sorter will be stopped if a container is in transit to a lane and the lane is no longer available and the container cannot be re-assigned to a different destination.  The SrtZoneLane table can be configured to define the type of lane (TwoSidedShoe) and the side of the sorter the lane is on (RightSideDivert).  Some reassignments may not be physically possible.
Reassign and Recirc:  For applications where the sorter has recirculation and containers are assigned to multiple destinations. Containers will be dynamically reassigned to down-stream lanes if the current assignment becomes unavailable.  The SrtZoneLane table can be configured to define the type of lane (TwoSidedShoe) and the side of the sorter the lane is on (RightSideDivert).  Some reassignments may not be physically possible.
LogLevel
PopUp
Select the log level for the sorter.  Level 2 is a good choice.
CartonIdUpdate
Radio
Select this to change the ConfirmScan value in the tracking table to the string received in the CSM or CRR response message.  Deselect this to leave the ConfirmScan string unchanged.  This feature may be used if the CartonID string must be parsed by CommCore and returned as a new string.
This feature may be tested using a CRR message and the “SrtTest” or “SrtTestSeq” protocol.  These protocols simulate CommCore.  If the SendTestCRR table, Param1 column, Row 1, is set to the “CartonIdUpdate1” string, the first parameter of a comma-delimited string will be returned.  If the column is set to the “CartonIdUpdate2” string, the second parameter of a comma delimited string will be returned.
CrrMsgTable
PopUp
Select the table to use for CRR messages.  Each sorter should use its own separate message table to prevent delays in processing sorter lane assignment.  Select the MsgCR1 table for the 1st sorter.  Nine tables are available to choose from.
DcmMsgTable
PopUp
Select the table to use for DCM messages.  Start with the MsgDC1 table.
CsuMsgTable
PopUp
Select the table to use for CSU messages.  It is OK to share the MsgDC1 table for this use.  If the CommCore configuration expects CSU messages on the same port as DCM messages, use MsgDC1, otherwise choose another table such as one of the MsgGP tables not in use elsewhere.
CsmMsgTable
PopUp
Select the table to use for CSM messages.  Each sorter should use its own separate message table to prevent delays in processing sorter lane assignment.  Select the MsgGP1 table for the 1st Sorter on this PC.  CSM Messages are only sent if the SendCRRUpdatePt is selected in the SrtScanBoss table for the sorter.  This feature is used in applications where the scan event needs to send a CSM first, then later send a CRR.  The CSM is sent at the scan update point, the CRR is sent at the update point selected in the SendCRRUpdatePt column.  This is done to give CommCore time to retrieve routing information from the customer’s host system.
SecondCrrMsgTable
PopUp
This is used if a second scan point is designated on a sorter.  It is activated if SrtScanBoss_SecondScanZone is populated.  Choose a message table to handle the second CRR messages.
SecondDcmMsgTable
PopUp
This is used if a second scan point is designated on a sorter.  It is activated if SrtScanBoss_SecondScanZone is populated.  Choose a message table to handle the second DCM messages.
SecondCsuMsgTable
PopUp
This is used if a second scan point is designated on a sorter.  It is activated if SrtScanBoss_SecondScanZone is populated.  Choose a message table to handle the second CSU messages.
